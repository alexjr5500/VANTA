# Cross-server realtime readiness

Socket.IO Redis pub/sub is optional and disabled by default. Set VANTA_SOCKET_REDIS_ENABLED=true only in isolated staging with a dedicated private VANTA_SOCKET_REDIS_URL, an environment-specific VANTA_SOCKET_REDIS_PREFIX (e.g. vanta:acceptance:socket), and VANTA_SOCKET_REDIS_TRANSPORT=websocket or sticky. Websocket-only mode disables polling fallback; verify all supported browser/Android clients and networks before using it. Sticky mode preserves polling but requires actual load-balancer session affinity, which this application does not configure or prove.

The adapter uses separate publisher/subscriber connections and installs before HTTP listens. An initial connection failure prevents startup instead of silently falling back to local rooms. A disconnected adapter marks /health/ready unavailable and rejects new socket handshakes. This is a client connection signal, not an end-to-end pub/sub probe. Existing clients can still miss events during Redis outages. Redis pub/sub is not durable or a guarantee of delivery; persist critical state in PostgreSQL and reconcile on reconnect. Existing authorization middleware and event payloads are unchanged. A dedicated private Redis service and restricted access are required; do not mix environments.

CI starts two independent Socket.IO servers with a disposable Redis and test-only authenticated identities, checks remote room lookup, targeted event delivery and exclusion of a different user. This is not complete VANTA multi-replica acceptance. The existing presence registry, socket rate limits, live stream role caches and legacy call gating are process-local; distributed presence, push deduplication, moderation/role consistency, per-user socket limits and scheduled sweep ownership remain blockers. Before scaling, verify real chat, notification, live/gift, moderation and call flows across replicas; confirm no unauthorized delivery, reconnect recovery and client transport support. Keep production unchanged.
