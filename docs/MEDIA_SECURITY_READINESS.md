# Local media security hardening

The opt-in local HLS handler now restricts FFmpeg input protocols to file and formats to MOV/MP4 and Matroska/WebM; other formats fail rather than following arbitrary demuxer references. This is defense in depth, not a filesystem sandbox. Keep the worker isolated from secrets and restrict egress independently. Only the existing fixed encoding presets are accepted. All new variant outputs are validated before publication, and retries verify every master entry against generated rendition metadata and every referenced segment. Unexpected tags (including key/map references), duplicate/extra master entries and oversized playlists fail closed. Earlier noncanonical output must be inspected manually; never overwrite it automatically. Local temp cleanup refuses symlink aliases even inside the temporary directory. No production flags or assets changed.

The real FFmpeg test uses synthetic local video and checks rejection of disguised playlist input and unsafe existing master/variant playlists. Remaining gates: real byte/duration limits and resource quotas, isolated mount permissions and immutable source identity, Cloudinary credentials/provider isolation, private-media delivery, wallet and payment review, actual staging recovery. Filesystem path checks cannot fully prevent races with a malicious process that can write the worker volume.
