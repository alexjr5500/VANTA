# Realtime presence readiness

The main HTTP server delegates presence persistence to chat, instead of the global security disconnect handler unconditionally writing offline. Security audit logging remains active. Local per-user transitions are serialized and disconnect is registered before async work. With the opt-in Redis Socket.IO adapter, last-local-socket disconnect checks cluster room membership. A failed lookup or an unavailable adapter produces unknown, not offline; a conditional PostgreSQL update avoids overwriting a newer lastActive timestamp when possible. Existing audience privacy checks remain in place.

This is best-effort, not a strongly consistent distributed presence registry. Room snapshots can race reconnects, network partitions can hide peers, clocks can skew, and a killed process may not emit disconnect. A durable lease/reconciliation design and real staging crash/partition tests remain required. Push suppression remains local (extra device pushes are possible); do not suppress remote pushes merely from a room snapshot. Legacy call events, socket security limits and live roles require independent review before scaling. Two-server CI checks a shared user's last socket and unknown-state handling; unit tests cover local race and transition sequencing. No production configuration changes.
