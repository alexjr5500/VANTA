# HTTP telemetry and alert readiness

VANTA_HTTP_TELEMETRY_ENABLED=true enables process-local 60-second JSON log snapshots (vanta.http.window) and sustained alert events (vanta.http.alert). It records completed responses, actual 5xx counts/ratio, aborted requests, active requests and a fixed 16-bin latency histogram. P95 is an approximate upper bucket boundary; overflow is explicit. No raw paths, request bodies, user IDs or credentials are collected by the new tracker. The legacy metric tracker no longer uses raw unmatched request paths as metric names. With the flag enabled, the legacy HTTP alert rules are disabled in favor of the new windowed rules; legacy metrics remain available.

Initial thresholds: at least 20 completed requests in a window, at least 3 5xx and 5% 5xx ratio; p95 upper bound above 1 second or overflow; at least 20 total settled requests, at least 3 aborted and 10% abort ratio. Require two consecutive bad windows and five-minute per-code cooldown. No traffic means unknown latency/error ratio, not proof of health. These are provisional, process-level signals, not availability SLOs or global percentiles. Probes and all HTTP requests are included; aborted responses are not included in completion latency or 5xx denominator. Histograms must be summed across replicas with matching windows and bounds, never average per-replica p95. Timers stop on opt-in graceful drain. No alert destination or central aggregation configured yet.

Staging: validate synthetic success, error, slow and aborted requests in isolated testing, confirm logs arrive at the chosen collector, configure incident routing and deduplication, verify quiet/recovery windows and load overhead before enabling. Never intentionally inject production errors. Missing Cloudinary credentials and disabled worker activation currently block the separate acceptance stack (observed 2026-11-25); no production settings changed.
