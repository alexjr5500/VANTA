# Shared-only cache mode

VANTA_REDIS_CACHE_SHARED_ONLY=true is an additional opt-in for an isolated staging deployment with VANTA_REDIS_CACHE_ENABLED=true and a dedicated REDIS_URL. It bypasses both process-local data caches, so a shared Redis deletion or replacement is seen by subsequent reads from another instance. Redis misses or connection failures return cache misses, not stale local values; counter failure throws instead of pretending a local increment is globally authoritative. Global flush is refused. Prefix invalidation uses awaited scan/delete batches.

This is a correctness-first tradeoff: extra Redis round trips and database load on cache outage. No distributed tags, pub/sub notification delivery, Socket.IO adapter, security rate limit authority, cache-aside write-race guarantees, or distributed task locks are implemented by this change. Failed cache writes/deletions can still leave shared values until expiry; do not cache authorization, wallet or other consistency-critical decisions. Review call sites and failure semantics, use separate staging Redis, and test outage/recovery, concurrent invalidation and actual app replicas before enabling. CI exercises independent Redis clients, not a multi-server production deployment. Production settings remain unchanged.
