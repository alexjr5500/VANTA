# Live gifts, recovery and reconciliation release gate

Live crypto gifts require VANTA_SHOP_LIVE_GIFTS_ENABLED=true in addition to the existing dedicated live checkout gate. Recipients are fixed when the order is created and rechecked under DB locks during fulfillment; active/suspended gift badges are rejected. Coin purchase quantity is exact with no bonus. No recurring billing or Android Play Billing changes.

A dedicated invoice stores independently verified exact payment hash, timestamp and sender where available. Only a verified dedicated invoice can recover an expired order. The chain proof must still show payment within the ORIGINAL invoice window. Legacy checkout cannot use the recovery exemption. Monitor recovery scans the last seven days plus known attached hashes, and an owner can supply an older exact hash. Ineligible or late/partial/excess/wrong-asset payments require reconciliation, not automatic fulfillment. Recent orders and cases are payer-scoped, including after checkout is disabled. Closed invoices must never request another transfer.

Payers can open one auditable payment case per invoice. Admin > Payment cases is restricted to CEO/SUPER_ADMIN and fresh TOTP for state changes. A refund case blocks fulfillment and pending treasury processing. A payment review cannot unwind a previously dispatched external transfer: reconcile externally first. Case records cannot mark a refund successful from an unverified hash.

Narrow external refund workflow: VANTA_SHOP_EXTERNAL_REFUNDS_ENABLED=true and live checkout, only verified unfulfilled unswept USDT BEP-20/ERC-20 or USDC Base. Authorized admin reviews original sender ownership (not an exchange deposit or unreviewed smart contract), confirms exact original sender address, and records instruction. Approved custodian executes outside VANTA, from the original receiving wallet, exact token amount, fees separate. Verify exact outgoing on-chain proof before atomic order/case REFUNDED transition. No private keys, no custody adapter broadcast, no actual transfers. Existing dedicated crypto orders must not use legacy ledger-only reversal endpoints. Fulfilled orders, swept funds, ETH/TRON/TON refunds, non-exact or late transfers, exchange-origin payments, cancellation/reopening of cases, and entitlement reversal with external refund require a separately reviewed financial workflow. No production activation. Controlled and concurrent database tests plus external custody testing are release blockers.
