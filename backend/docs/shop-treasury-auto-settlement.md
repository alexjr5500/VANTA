# Automatic treasury settlement (initial stablecoin rails)

This code implements the VANTA side of a durable custody orchestration protocol. **No custody provider is deployed or connected by this change; no transfer is enabled.** Automatic sweeps initially support USDT on BSC and Ethereum, and USDC on Base. ETH, TRON and TON outgoing automation remains disabled. No private key or recovery phrase belongs in VANTA. A policy-controlled external custody signer must own the unique invoice addresses and separately fund their gas balances.

## Fail-closed configuration
- Existing treasury public destinations for each approved chain (see shop-treasury-release-gate.md).
- VANTA_TREASURY_AUTO_ENABLED=true and VANTA_TREASURY_CUSTODY_VERIFIED=true after operator approval, migration and controlled end-to-end validation.
- VANTA_TREASURY_AUTO_NOT_BEFORE (explicit ISO timestamp; only eligible invoices settled since then are queued).
- VANTA_TREASURY_AUTO_NETWORKS (comma-separated subset of usdt-bep20,usdc-base,usdt-erc20).
- VANTA_TREASURY_AUTO_MAX_ORDER_CENTS, VANTA_TREASURY_AUTO_DAILY_CAP_CENTS (integer USD cent limits).
- VANTA_TREASURY_BSC_MAX_FEE_WEI, VANTA_TREASURY_BASE_MAX_FEE_WEI, VANTA_TREASURY_ETHEREUM_MAX_FEE_WEI as applicable (integer native atomic fee caps, including all rollup fees).
- VANTA_TREASURY_SIGNER_URL (dedicated trusted HTTPS origin), VANTA_TREASURY_SIGNER_POLICY_ID, VANTA_TREASURY_SIGNER_HMAC_SECRET (strong independent random secret in secrets manager). Trusted network egress and verified provider TLS are required.

## External custody adapter contract (not an existing vendor API)
PUT /v1/settlements/{requestId} receives the immutable JSON intent with requestId, policyId, network, chainId, tokenContract, source, destination, amountAtomic, maxFeeAtomic, incomingTransactionHash, expiresAt. GET on the same path returns current status. Headers X-Vanta-Timestamp, X-Vanta-Nonce, X-Vanta-Signature, Idempotency-Key. Signature is lowercase hex HMAC-SHA256(secret, ["vanta-treasury-request-v1", METHOD, PATH, TIMESTAMP, NONCE, RAW_BODY].join("\n")). Verify freshness (e.g. 60 seconds), nonce uniqueness, constant-time MAC and exact method/path. Responses must be JSON with X-Custody-Signature hex HMAC-SHA256(secret, "vanta-treasury-response-v1\n" + request nonce + "\n" + exact raw response body). Status: accepted/pending/broadcast/rejected, or authenticated not_found for GET only. Echo all intent fields except not_found (requestId and policyId still required). Broadcast additionally returns transactionHash and approvedFeeAtomic. The signer MUST durably deduplicate by requestId **and invoice source/chain/asset/incoming hash**, reject mismatched immutable payloads, enforce independent allowlists, per-order/daily/fee caps, direct token transfers only, key ownership and nonce handling, no arbitrary calldata, and expiry. It must persist the signed transaction before broadcast and recover using the same signed transaction, never generate another transfer for an ambiguous request. The signer must enforce fees before signing; VANTA checks actual outgoing fees afterward. Do not expose a general-purpose signing API or accept destinations from users. No automatic gas funding is included.

## Worker behavior
One DB transfer per invoice, one unique request ID, multi-worker compare-and-swap leases, serialized queue/dispatch caps, independently reverified incoming payment, current token/gas balance and estimated fee preflight. Persist AUTO_DISPATCHING before the single external PUT. If a response is lost or process crashes, poll the immutable request via GET only. An unresolved/missing record after the deadline goes to AUTO_REVIEW; no automatic resubmission or manual broadcast path for automatic rows. Signed response is not proof of settlement: verify direct outgoing calldata, official token event, sender, destination, exact atomic amount, canonical receipt and confirmations, plus actual fee (including Base L1 fee) before VERIFIED. A fee exception remains review even if funds moved. All state transitions affecting transfer authorization/verification have atomic audit records. Daily limits are in UTC and use original USD order values, not current exchange prices. Disabling the worker prevents new requests but cannot cancel an already accepted external transaction; halt the custody policy as well. Recovery of unknown/failed transactions requires independent custodian and on-chain reconciliation. No production wallet, private keys or real transfers have been configured.

## Required before activation
Select a regulated/appropriate custody arrangement and implement its adapter; review and test protocol, key custody, withdrawal policy, fee accounting, chain RPC correctness, gas funding, destination ownership, refund reserve and limits. Apply migrations, run PostgreSQL concurrency/crash tests, test forged/replayed responses, ambiguous requests, signer outages, chain reorganizations, fee breaches, and tiny controlled transfers on each approved network. Keep automatic settlement and live checkout off until validated. No Play Billing work.
